# 速度APIの確認と修正提案（2026-11-13）

今回のTranscriptionServerソース `40fe872` の仕様は参考情報の表示には使えるが、音声の処理速度比較や終了予測へそのまま使うには不足がある。サーバー本体は変更していない。

## 確認した契約とクライアント対応

- 正本: `C:/develop/Services/transcription-server/docs/model-information.md`、`src/model_info.rs`、`dist/model-metadata.json`。
- `/api/health` の `capabilities.modelInformation` と `/api/models` が新しい全件情報API。従来の `/v1/models` にも `x_meeting.modelInfo` が追加される。
- TranscriptCutterは従来の `/v1/models` の選択候補を使い続け、埋め込まれた `modelInfo.referenceSpeed` を表示する。全件情報APIから未対応モデルを候補へ追加しない。別のAPI呼び出しやプロキシ公開範囲の追加は不要。
- `historical_measurement` / `characters/s`、モデルID、算出元と速度の整合性を検証。過去の文字/秒、CPU、方式、当時の版、音声・ロード・話者分離の条件、注意事項を表示する。参照情報なしは「未提供」、未測定または不正値は「未測定」。HTMLとして解釈しない。
- ブラウザー側の音声倍速と終了見込みには使用しない。選んだ処理方式の現在値だとも扱わない。

## 問題点と追加提案（未実装）

|問題|提案|理由|
|---|---|---|
|出力文字/秒は認識内容・反復・句読点・言語で変わる|`audioSeconds`、`audioSecondsPerRunSecond`、`realTimeFactor` を追加。分母を `runSeconds` と明記|同じ音声で比較でき、反復が多いほど速く見える逆転を防ぐ。文字/秒は別の参考指標として維持|
|旧測定は初回ロード、常駐、話者分離、音声がモデルごとに異なる|条件を文字列だけでなく `loadState`、`diarization`、`sourceKind`、`sampleCount`、`measuredAt` として返す。既存条件文は保持|同条件の標本だけを選択し、単発/複数回の区別を付けられる|
|CPU/GPUやモデル表現が違う標本を比較しやすい|`actualDevice`、`backend`、`computeType`/`dtype`、`modelRevision`、`serverBuild` を測定標本に保存|GPU指定と実際のCPUフォールバック、旧版と現在版、量子化方式を区別できる|
|参考環境が接続先PCの現在の速度と混同される|既存 `kind=historical_measurement` と参考環境を維持し、将来の当該インスタンス実測は別フィールド/別kindで返す|参考値で現在PCの終了見込みを計算しない|

追加値を計算できない旧記録は `null` とする。音声長は最後の字幕の終了ではなく実際に認識した入力範囲を使う。途中終了/失敗を完了60秒の標本へ混ぜない。待機・アップロードを含まない `runSeconds` の既存定義を維持し、話者分離との並行工程を合計して全工程時間を作らない。単位と算式をスキーマに固定し、既存フィールドの意味を途中で変更しない。

今回のブラウザー測定でもCPUは487文字、GPUは190文字となったが、CPU側には同じ語句の大量反復があった。文字/秒だけでは字幕品質や実用的な処理能力の比較にならない。正解字幕による精度評価は速度と別に行う。
