# v4.2.0 実装計画・報告書

## 設計

- Windows x64・ユーザー単位のインストーラーを追加。Inno Setupを使用し、管理者昇格・Windowsサービス・自動起動・LAN公開を新設しない。EXE/ランタイムとユーザーデータ・設定・更新キャッシュを分離し、アンインストールでもデータと設定を保持する。
- インストール版は既定8769・loopbackで起動し、起動オプションをユーザー設定へ保存して更新後も引き継ぐ。既存の明示CLI・保存先・認証は維持。開発ソース版からのインストール更新適用は無効にする。
- 非公開i1643/TranscriptionServerの最新安定版を固定のGitHub APIから確認。起動後と24時間間隔、または手動確認。ダウンロード・再起動は利用者が「更新」を明示した時だけ行う。
- 別PCでもGit不要。更新用GitHubトークンは環境変数またはWindows資格情報マネージャーで保持し、Web画面では保存済みかどうかだけ返す。認証値を応答・ログ・更新計画・設定JSONへ残さない。
- 更新の変更操作はサーバーPC上のloopbackからのみ受け付け、既存の変更操作認証とorigin制限も維持。録音ジョブ中は更新を拒否。更新直前は新規受付を止める。
- GitHubの公開済みReleaseにある期待名のsetup-x64.exeだけを取得。バージョン・最大容量・SHA256 digestを検証し、他ホストへの認証ヘッダー転送を防ぐ。失敗・不明状態では適用しない。
- 独立した更新ヘルパーが親プロセスの終了を確認し、アプリファイルをバックアップしてサイレントインストール、同じ設定で再起動しhealthを検証。適用失敗はファイルを復元して旧版を起動し、結果を更新キャッシュへ保存。データは更新・復元の対象に含めない。
- 本PCの既存サーバーを二重起動しない。専用パス/ポート/データでインストール・更新・アンインストールを検証した後に、既存18ジョブを保持する移行を行う。
- API/protocolVersion=3は維持。バイナリとsetup、ソース、SHA256を非公開GitHubへ新規版として公開し、過去Releaseは上書きしない。

## フェーズ3結果と修正

- Inno Setupでユーザー単位のsetup-x64.exeを生成。プログラム/データを分離し、スタートメニュー・任意デスクトップアイコンに対応。通常の起動中上書きと旧版へのダウングレードを防止する。
- 専用フォルダーで実インストール・同版再導入・起動・アンインストールを実施し、設定・字幕・録音の保持に成功（Services/runtime/transcription-v4.2.0-installer-final/result.json）。
- 実通し試験で、終了済みプロセスのHANDLEが残るとcreation timeだけでは終了を認識できない事象を発見。Windows WaitForSingleObjectの終了状態を確認し、実HANDLEによる回帰試験を追加した。
- 深い更新キャッシュのバックアップ先で、263/267文字の2ファイルをコピーできない事象を発見。Windows拡張パスを使ってバックアップ/復元し、診断error.logと復旧後PIDも記録する。失敗試験では適用前に中断して旧版再起動を確認し、録音・字幕は保持された。
- 修正後の実通し試験に成功。v4.1.0の実ZIPへ新ヘルパーと導入markerを加えたテスト専用基準から、非公開GitHub draftの実assetを認証取得し、SHA256照合・実Inno適用・v4.2.0再起動・保存先/設定/字幕/録音・プログラムとSQLiteバックアップを確認した。draftメタデータの安定版相当への正規化は試験コードだけで行い、製品はdraftを採用しない（Services/runtime/transcription-v4.2.0-self-update-verified/result.json）。
- 最終Python92件・JavaScript91件が成功。配布EXEのWhisper Tiny/CPU実認識・認証・2回目のモデル再利用（読込0秒）・realtime枠・中止も成功。合成音声だけを使用した。

## 本PCの導入

- `%LOCALAPPDATA%\Programs\TranscriptionServer` へインストールし、基本サーバー8769を導入版へ移行。保存先は既存Services/runtime/transcription-server/dataを維持した。
- 移行直前は19ジョブ/処理中0件。SQLiteスナップショットを取得し、前後の全ジョブID・全字幕行のハッシュ・録音ファイルのサイズ/更新時刻が一致した。DevServer用ラッパーで停止/再起動し、ready・v4.2.0・導入版の更新機能・所有プロセス記録を確認した。
- Startラッパーは導入版を優先し、speech/FFmpeg/データ指定を継続。PowerShellの単一要素配列が文字列になる引数連結を修正。Stopは検証済みの所有ツリーを停止し、venvのランチャーだけが終了する状態を防ぐ。Services自体は非Gitで、本体の配布コードとは分離する。
- 更新用GitHubトークンは未登録。利用者が画面で初回設定するかTRANSCRIPTION_GITHUB_TOKENで指定すると自動確認が有効になる。端末の既存Git認証値を勝手に製品の保存領域へコピーしていない。
