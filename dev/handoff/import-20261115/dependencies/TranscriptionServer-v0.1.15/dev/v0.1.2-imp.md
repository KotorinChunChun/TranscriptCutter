# v0.1.2 実装計画・報告

## 版番号の訂正（2026-11-12ユーザー指定）

旧呼称v0.4.0の機能をv0.1.2として再採番する。以下の旧版名・旧成果物ハッシュは実際に行った検証の記録として残す。再採番版は内部版とファイル名を揃えて再ビルドする。旧0.2.0/0.3.0/0.4.0のRelease/タグはローカル退避・訂正版公開後に撤回する。Git履歴と稼働中の旧EXE/データは変更しない。

## 設計

- 公式NeMo-Speech.cpp v0.3.0のWindowsネイティブCLIを、旧speech.cppと別の実行環境として追加する。Pythonは既存Whisper専用のまま。CLI/HTTP/ジョブ管理はRustを維持する。既存の8769とAI Room検証用18769を更新・停止しない。
- engine=nemotron-asr、model=nemotron-3.5-asr-streaming-0.6bを追加し、task=transcription、文字起こし専用、話者識別は既存Nemotron分離器との組み合わせとして広告する。一体型3.5 Transcribe、分離専用3 Diarizationと混同しない。
- 録音は既存ジョブへ、リアルタイムは既存の30秒以下ジョブ枠へ接続する。ネイティブのキャッシュ付きストリーミング認識と、サーバーのWebSocket/要求間連続セッションは区別して能力を返す。後者を実装済みとしない。
- 公式Q8_0重みは742,090,464バイト、固定revision ea30d66debe3740a08b573244286791d423d6b3e、SHA256 3fc991d3badad7277c11030a7519832cddaf2057aafed6d4b25147e953a070b1。新しい開発・検証用キャッシュへ導入し、日本語合成音声で実CPU認識を確認する。30Bモデルは取得しない。
- 公式CLIのJSON形式・言語指定・GPU列挙・モデル導入を実物で照合してから確定する。モデル管理は導入と認識時のロード/解放を正直に表示し、非対応の常駐ロードを成功表示しない。
- M4000の552.86は前回CUDA12.8.1構成の基準572.61未満。ドライバーの対応製品を確認した上で更新を案内するが、実機の変更はしない。WhisperのSM52コード不足と新C++モデルのVulkan経路は別の条件として扱う。

## フェーズ1 実装・ソース検証

- 追加Pythonなしで独立したNeMo-Speech.cpp CLIを使う経路を実装。固定モデル、ja-JP既定/auto/公式32対応locale、録音300秒単位と30秒以下realtime枠の--stream、元時刻への復元、CPU/明示Vulkan、既存DiarizationとのCPU併用に対応した。autoはCPUへ確定し、未導入重みの自動取得やモデル代替はしない。
- 管理画面は新モデルのインストール/再点検/認識時ロード・解放を表示。手動常駐ロードは未提供として無効化した。固定HTTPS URL、サイズ、SHA256、ディスク残量、取得中止と所有一時ファイルのDrop時掃除をRustで実装した。モデル重みは配布物に含めない。
- CLIのmodel-indexは実行ファイルの相対位置に依存するため、配布時のshare/nemo-speech/model-index.jsonを明示して呼び出す修正を行った。最初の隔離試験でモデル管理が利用不可となった問題をこの配置照合で解消した。
- Rust20試験、Web96試験、Whisper Python2試験、fmt/clippy（-D warnings）成功。言語/役割、本文欠落防止、概算時刻の明示、旧API/字幕/中止/キュー/移行・再開の回帰を含む。PowerShellセットアップの構文とライセンス/台帳同梱も点検した。
- 日本語合成2話者音声23.254438秒をソースEXEから実CPUで認識し3区間、初回受付から10.64秒で完了。2〜10秒の範囲、auto言語のrealtime5秒、無音、Nemotron分離器併用、中止/後続回復、未導入503、対象外locale400、管理の再点検/導入済み確認を通した。本文には認識誤りがあり、実会議精度の受入とはしない。証拠: Services/runtime/transcription-nemo-0.4-source-verified/result.json。
- 調査段階の公式CLI単体でも同じ合成音声から日本語本文と時刻を取得（約12.66秒）。固定Q8_0 GGUFは公式revision/742,090,464バイト/SHA256を照合した。これとは別に、配布物でRustの実ネットワーク取得経路を検証する。
- ユーザー指定の台帳に従い、TC/MVのエンジン許可一覧とAI RoomのASR専用分類対応を各担当チャットへ送信。送信と担当側完了・実接続を区別する。8769と既存18769を更新・停止しない条件も伝えた。
