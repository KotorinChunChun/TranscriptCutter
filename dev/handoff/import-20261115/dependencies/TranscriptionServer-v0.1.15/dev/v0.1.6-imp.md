# v0.1.6 実装計画・報告

## 背景

v0.1.5の技術検証（[v0.1.5-imp.md](v0.1.5-imp.md)「実会議音声300秒の比較と分割の技術検証」）で、Nemotron ASR（NeMo-Speech.cpp CLI、CPU）は1回に渡す音声が長いほど処理時間が急増した（300秒1回410秒、60秒×5で120秒）。無音＋話者の切り替わりで最大30秒に区切る試作は74.1秒だった。字幕の文面は変わる（300秒1回との文字一致率0.912）ため、ユーザー承認のうえv0.1.6で採用する。

## 設計

### 分割規則（file処理）

1. 処理範囲の16kHz mono WAVを1回だけ作り、speech.cppのsilero-vad（`--speech-pad-ms 200`、`--min-silence-duration-ms 300`、最大発話長は既定の無制限）で発話区間を得る。
2. 発話区間を時刻順に塊へまとめる。塊の先頭から次の発話の終わりまでが30秒以内なら同じ塊へ足し、超えるなら新しい塊を始める。塊と塊の間の無音は送らない。塊の中の短い無音はそのまま送る。
3. 話者の切り替わり: 話者分離を認識より先に実行する直列時だけ使う。各発話の話者は話者区間との重なりが最長の話者。直前の発話と話者が異なれば、30秒以内でも新しい塊を始める。ただし今の塊が4秒未満なら切らない（短い相づちで細切れにしない）。重なる話者がない発話は切り替わりとして扱わない。
4. 無音のない1発話が30秒を超える場合は切らずに1つの塊とする（文脈を保つ、ユーザー回答）。300秒を超える場合だけ300秒ごとに切る。
5. 前後の余白で発話区間が重なる場合は、直前の塊の終わり以降だけを送り、同じ音声を二重に送らない。
6. 塊のWAVは全範囲WAVから該当サンプルを直接切り出して書く（v0.1.5のPcmReaderと同じFFmpeg互換のサンプル範囲）。塊ごとのFFmpeg起動をなくす。

### 適用範囲・フォールバック

- realtime（30秒以下）は従来どおり範囲全体を1回で`--stream`認識し、VADを行わない。
- 認識GPU（Vulkan）＋話者分離CPUの並行時は認識開始時に話者区間がないため、無音だけで区切る。結果がタイミングに依存しないよう、並行時は話者区間が先に出ても使わない。
- speech.cppまたは導入済みのsilero-vad重みがない場合は、自動取得せず従来の300秒固定分割で処理する。
- 選択した方式をmetadataに記録する: `audioChunking`（`vad_speaker` / `vad` / `fixed` / `realtime`）、`audioChunkMaxSeconds`（30、固定時300）、`continuousSpeechMaxSeconds`（300）、`audioChunkCount`。従来の`audioChunkSeconds`は塊の上限秒数の意味で残す（vad系は30）。
- 進捗のprocessedUntilは各塊の終わり（最後は範囲の終わり）。話者付与・SpeakerGate・API契約（protocolVersion=3）は変えない。

## 検証方法

- 単体テスト: 分割規則（30秒結合、話者切替、4秒未満は切らない、長い連続発話は300秒まで1塊、300秒超の分割、重なり除去、話者なし）、WAV書き出しのヘッダーとPCM。
- cargo fmt / clippy -D warnings / cargo test、npm test。
- 隔離loopbackと別データで、実会議録音300秒をv0.1.5配布EXEとv0.1.6で交互・反復処理し、所要時間と字幕を記録する。通常稼働8769/18769/18770と別PCは停止・更新しない。

## 結果

### 実装

- `src/jobs.rs`: `nemo_chunks`（分割規則）、`dominant_speaker`（重なり最長の話者）、`wav_16k`（塊WAVの書き出し）を追加し、`nemo_asr`をVAD分割／300秒固定／realtimeの3経路へ整理した。Nemotron CLIの呼び出しと字幕の保存・進捗は共通の非同期クロージャーにまとめ、SpeakerGateの保留・話者付与はv0.1.5のまま。中止は塊ごとに確認する。作業用の`nemo-range.wav`/`nemo.wav`は成功・失敗とも削除する。
- `src/catalog.rs`: speech.cppのモデル一覧から取得済み重みを返す処理を共通化し、`installed_vad_file`を追加した（未導入なら取得しない）。
- 版をv0.1.5→v0.1.6（パッチ）へ更新: Cargo.toml/Cargo.lock/package.json、README、dist/index.html・management.html、docs（installation-updates/model-management/standalone-diarization/operations）。資料はdocs/nemotron-asr.mdとREADMEへv0.1.6の分割仕様を追記した。

### 検証

- cargo fmt、clippy `--all-targets -D warnings`成功。cargo test 39件成功（新規4件: 30秒結合と塊間の無音除外・重なり除去、話者切替と4秒未満の非分割・話者なし発話、300秒までの連続発話と300秒超の分割、重なり最長の話者とWAVヘッダー）。npm test 103件成功。
- 実会議録音300秒（16kHz WAV、2話者）をCPU・隔離loopback48000・別データで、v0.1.5配布EXE（release/v0.1.5）とv0.1.6（target/release）へ交互に投入した。`/api/jobs`は`diarize`省略時に話者分離が有効のため、無効の試験は`diarize=false`を明示して追加した。

### 未確認・制約

- Vulkan GPU認識との並行時（無音だけで分割）、realtime、silero-vad未導入時の300秒固定へのフォールバックは単体の分岐確認だけで、実機の通し試験はしていない。別PC/M4000/長時間（71分級）実会議も未受入。
- VADは処理範囲全体を1回で調べる（本PCの300秒で0.63秒、38区間、最長35.2秒の連続発話）。長時間録音ではVAD用の16kHz WAV（1時間で約115MB）を一時的に作る。
- 通常稼働8769/18769/18770と別PCは停止・更新していない。Release・利用アプリへの通知は未実施。
