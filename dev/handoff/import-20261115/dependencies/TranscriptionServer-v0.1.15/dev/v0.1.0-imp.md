# v0.1.0 実装計画・報告書

## 確定方針

- 2026-11-11ユーザー回答により、RustをCLI/HTTP/API/SQLiteジョブ管理/プロセス管理/更新処理の本体とし、Pythonはfaster-whisper認識ワーカーだけに限定する。Rustで旧Pythonサーバーを起動するラッパーにはしない。
- 前段v4.3.0のLAN・名称・起動点検の設計/試験を継承し、リリース版はユーザー指定のv0.1.0へ変更する。旧v4.2.0インストールとのバージョン番号逆転は、明示的なRust世代への移行として扱う。AppIdとデータ先を維持し、既存の公開タグを上書きしない。
- Rust本体はAxum/Tokio、rusqliteで既存jobs/segments/job_indexのJSONを保持する。配信・raw/multipartアップロード・字幕編集・ページング・Range再生・OpenAI互換応答・稼働/容量APIを移植する。変更APIとキューの競合は直列化し、終端状態を中止/完了の競合で戻さない。
- file/realtime各1枠、realtime30秒制限、GPU候補の直列化、各枠1Whisperプロセス再利用/180秒解放、処理中拒否と所有子プロセスの停止をRustが担当する。Pythonは標準入出力のJSON Linesで認識結果/進捗だけを返し、HTTP・DB・ジョブ状態を扱わない。
- speech.cppのネイティブASR/話者分離と外部API経路はRustから直接実行する。モデル名・時刻・話者スキーマ・明示選択を維持し、別モデル/外部APIへ自動変更しない。
- LANは実NICのプライベートIPv4サブネット/Host/Originへ限定し、healthのauthMode=lan/tokenでキー手入力不要。Bearerモード、loopback限定の更新管理も維持。起動時の重み点検はオフラインで行い、実推論成功とは分ける。
- 自己更新もRustの同一EXEを専用フォルダーへコピーして独立起動する。GitHub資格情報はWindows資格情報/環境変数、サイズ/SHA256検証、親終了確認、プログラム/DBバックアップ、同じ引数の再起動、失敗復旧を維持する。更新世代の識別により旧v4系を新版と誤認しない。
- インストーラーはユーザー単位を維持し、Rust EXE＋Whisper専用ワーカーを同梱。PythonのHTTPサーバーや更新ヘルパーは製品の実行経路へ入れない。FFmpeg/speech.cpp/モデルの保存場所と既存19ジョブを保持する。

## フェーズ

1. Rust基盤・旧DB互換・設定・LAN/認証・モデル点検・試験・コミット。
2. Rustジョブ実行・Whisper専用ワーカー・ネイティブ/API・HTTP契約、既存クライアント/合成音声/中止/再利用の試験・コミット。
3. Rust更新・インストーラー・世代移行と再起動/復旧・導入保持の試験・コミット。
4. DevServer/FWのLAN整合と本PC保持移行、TranscriptCutterの実LAN経路確認、非公開GitHubのソース/タグ/成果物Releaseと照合。

## フェーズ3 実装

- 更新確認・取得・適用ヘルパー・復元・Windows資格情報をRustへ移植した。GitHubの固定ホスト/HTTPS・サイズ/SHA256・Rust世代・版番号・親PIDと開始時刻・起動後の版と実PIDを照合する。処理/転送中は適用せず、プログラムとSQLiteを退避し、失敗時は所有ツリーだけ停止してプログラムを復元する。
- 通常終了APIはloopback限定とし、処理/転送/更新中は拒否する。HTTPの長時間接続が残っても終了は5秒で打ち切り、所有ワーカーの終了へ進む。

- cargo fmt、Rust13試験、clippy警告0、Web92試験が成功。Windows資格情報試験は専用の一意な試験エントリを作成・削除し、既存資格情報には触れない。サンドボックスではログオンセッションへ接続できなかったため、通常ユーザー環境で再試験して成功した。
- Windows資格情報/子孫プロセス終了、長いパスのバックアップ、更新計画/ハッシュ/世代/転送先境界を追加確認した。Windowsの信頼済み証明書をRustの外部HTTPSでも参照する。
