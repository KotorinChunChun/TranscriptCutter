# 必須ファイル保持検証の修正（未リリース）

## 実装前の計画

- 欠落していた通常設定を候補setup検証の `official()` が `if p.is_file()` で除外したため、前後とも欠落した状態を一致として扱っていた。容量整理も `normalSettingsExisted=false` を許容した。これらを保持成功の根拠にしてはいけない。
- `scripts/preservation.py` に、明示した必須ファイル・保持対象の存在/読み取り/SHA256確認、基準記録の妥当性検査、削除候補と保持対象の重複拒否を共通化する。設定・DB・導入EXE/BUILD/INSTALLATIONを更新前の必須対象とし、更新後のプログラム差し替えは保存データの不変検査と分ける。
- 既存の隔離setup検証スクリプトはこの共通検査を呼び、正式版の設定/登録欠落時にはインストーラー起動前に失敗させる。完了済み整理スクリプトは過去の不完全な計画で再実行・成功記録の上書きを行わせない。
- 今後の更新・整理手順とローカルAGENTSへ必須確認を記載する。過去の成功報告は削除せず、欠落により保持検証として不十分だった旨を追記する。
- 一時フォルダーだけで、欠落前後・ハッシュ変化・壊れた設定・不完全な基準・保護対象を含む削除計画・正常系を検証する。実setupの再実行、稼働APIへの接続、モデル取得、公開済み成果物の変更、リリースは行わない。
