# v0.3.0 実装計画・報告

## 設計

- 追加APIをv0.3.0としprotocolVersion=3を維持する。POST /api/jobs?engine=diarization&model=nemotron-3-diarizationで既存のraw音声転送、file枠、状態・中止・segmentsページングを再利用する。ASRとVADを実行せず、既存diarize処理で元時刻へ復元した各区間をtext空文字・speaker互換値・speakers配列として保存する。
- ネイティブモデル台帳の対象型の重みが全て取得済みの場合だけ単独分離をreadyにする。実行前にも再確認し、重みがない場合は503で明示拒否する。既存ASRの初回取得方針には手を加えない。CPU/明示GPUを使用しautoはCPUへ確定して実デバイスを記録する。
- /api/healthのenginesと/v1/modelsのx_meetingへtaskを追加。単独分離をASR UIへ混ぜないよう同梱クライアントのtaskフィルターを追加する。TC/MVは既存のエンジン許可一覧で除外することを読取確認済み。/v1/audio/transcriptionsから分離専用taskを呼ぶ場合は拒否する。
- 3.5 Transcribeは未設定・未導入の独立エンジンとしてhealthで理由を返し、実行可能な/v1/modelsへ混ぜない。NIMの別GPU/Linux API連携が候補だが今回は接続先・重みがなく認識経路は実装しない。追加Python/大量取得/GPU設定変更は行わない。
- ソース・開発文書・試験を更新してフェーズ単位で検証/コミットする。次に成果物作成と合成音声の実CPU試験を行い、処理中0・所有確認・設定/DB/媒体バックアップと照合の条件を満たす場合に本PCのみを更新する。

## 検証方針

- Rustで分離区間の時刻・話者・無音・不正入力、選択/未導入拒否とASR未呼出を確認する。HTTPの実転送・状態・ページング・中止・キューを模擬ネイティブ実行形式で試験する。
- Rust fmt/test/clippy、Node既存試験、Whisper Python既存試験、Windows release buildを実施する。既存のNemotron+ASRも合成音声で回帰確認する。
- 実配布物のAPI/能力とデータ保持、版/BUILD/成果物SHA256を照合する。長時間の実会議品質、別PC、M4000 GPU、3.5の実推論を合成CPU検証と混同しない。

## フェーズ1結果

- 単独分離を既存ジョブ経路へ追加し、録音内の話者ID・重複・元時刻と空text/speakersを保存する。ASR/VAD経路へ入らない。autoはCPUへ確定し、明示gpuは既存ネイティブ能力に従う。未導入や取得済みファイル消失を受付時/実行時に再点検し、分離器へ固定した既存GGUFファイルを渡して自動取得を防ぐ。
- /v1/modelsへ独立task=diarizationを広告。同梱ASR画面はtaskで除外し、TC/MVは既存のエンジン許可一覧で除外するため直接変更不要。旧ASRの行はtask=transcriptionを追加した以外のフィールドを維持。3.5はhealthでunconfigured/unavailable/not_configuredと理由を返し、実行一覧から除外する。
- Rust 18件、Node 95件、Whisper Python 2件が成功。fmt/clippy（-D warnings）も成功。Windows HTTP統合試験はC#製のローカル模擬実行形式をテスト時だけ作り、ASR/VADを呼ぶと失敗する方式で分離・区間・ページング・無音・不正出力・キュー・実行中/待機中の中止・後続回復・未導入503を確認した。
- 最初の制限環境では既存の資格情報試験がログオンセッション不足で失敗し、通常ユーザーで再実行して通過。追加試験の旧C#コンパイラー用パス指定も修正して全件再実行済み。既存資格情報は読取/変更せず、試験専用の一時対象だけを使用した。
- 本PCの読取確認ではIntel UHD Graphics 770。Nemotron Q8_0（106,179,488バイト）は取得済み。本PC8769はv0.2.0で処理中1件があり、この時点では停止・更新しなかった。別チャット送信は自動承認レビューに拒否されたため、それ以降は送信せず本チャットへ最終報告を残す。
