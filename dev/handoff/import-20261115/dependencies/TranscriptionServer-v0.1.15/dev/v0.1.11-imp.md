# HTTPS・一括モデル管理の実装計画（2026-11-14）

## 方針

- 当初v0.1.10の未リリース修正として実装。その後ユーザーが本PCのHTTPS併用切替を承認したため、app-version-updateに従ってパッチだけ上げたv0.1.11を本PCへ適用。初回の本PC適用では公開/インストーラー作成を行わず、その後の追加指示で正式リリースを実施した。既存v0.1.10の公開タグ/成果物は上書きしない。
- 既存共通CAを利用する。公開manifest/公開証明書/鍵ACLを確認済み。現在のサーバー証明書はSANに192.168.49.12/127.0.0.1/::1、sample-pc/localhostを含み、2027-10-15まで有効でServer Authentication用途。現在のユーザー/マシンRootには同CAが登録済み。CAや共通サーバー証明書を再発行・上書きしない。秘密鍵の内容を出力/Git/配布へ出さない。
- Rustへ任意のtls-cert/tls-key設定を追加し、8769でHTTPSと既存HTTPを併用できる接続リスナーを実装する。TLSだけを許す設定も用意する。既存HTTPクライアントを維持し、HTTPSを案内URLにする。同じ割当済みTCP8769なので追加ポート公開は行わない。
- TLSはハンドシェイクを各接続のI/Oで非同期に完了し、受付全体を止めない。期限を付け、不正TLSを平文HTTPへ再試行しない。元のTCP接続元情報を維持し、転送ヘッダーで更新APIのloopback制限を迂回させない。
- 利用PCへ配布するのはRootCA公開CERだけ。Subject/拇印/SHA256を別経路で確認して本人/管理者が信頼登録する手順を作り、信頼ストアはこの作業では変更しない。別サーバーIPは同CAでSAN入りの新しいサーバー証明書を管理者が発行する説明も付ける。
- 一括処理は既存の受付排他/中止と単体install/deleteを使い、対象モデルのIDを開始時に固定して直列実行する。対象は管理対象のローカルモデルのみ。disabled_by_policy/displayOnly/unsupportedは含めず、19GB一体型は除外。削除はモデル重みだけで、録音/字幕/設定/ランタイム/資格情報は保持する。
- 一括削除は対象一覧を示す自作確認を1回出す。単体/一括の導入確認は出さない。ロード済みモデルは無断解放せず削除対象から除外して理由を示す。個別エラーは集計して次へ進み、中止要求では残りを処理しない。
- 対象モデル行に導入中アニメーション、取得サイズが分かる時の実数ベース進捗率、未知時の不定進捗と現在対象/処理件数を表示する。偽の推定パーセントは表示しない。
- ランタイム差し替えの反映待ちと重み取得を区別する。上部の再起動通知は実際に反映待ちの対象を列挙し、再起動まで表示する。ユーザー回答に従い「進捗・再起動だけ固定、完了は各行」とする。
