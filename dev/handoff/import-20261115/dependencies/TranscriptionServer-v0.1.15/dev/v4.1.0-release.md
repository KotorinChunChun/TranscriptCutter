# TranscriptionServer v4.1.0

## 改善

- 待機中ジョブの中止後の解放、完了と中止の競合を修正。
- file/realtimeの独立処理枠を追加。GPU非対応時のautoもCPU枠として分離。GPU候補はメモリ確保を抑えるため直列化。
- Whisperのモデルを最大1プロセス/枠で再利用。モデル変更・失敗・中止・180秒のアイドル・終了時に解放。
- Windows強制終了時も常駐モデル等の子プロセスを残さない保護を追加。
- clientId/workloadによる分類、SQL履歴ページング、待機/読み込み/実行時間、稼働・容量APIとWeb管理表示を追加。
- 完了ジョブの録音だけを明示確認で整理。字幕・編集・ジョブIDは保持し、自動削除はしない。
- Windowsコードページに依存しない子プロセスJSON通信へ修正。

## 配布物

- Windows x64 ZIP：EXEとWhisper CPUランタイム、Web画面、ライセンス、依存一覧。Pythonの事前導入は不要。EXEだけを取り出さず、フォルダー全体を展開。
- ソースZIP、SHA256SUMS.txt。
- モデル、FFmpeg/FFprobe、speech.cpp、CUDAは同梱しない。必要なエンジンに応じて別途配置する。
- 認証情報、録音・DB、PC固有台帳は含めない。

## 互換性と検証

- protocolVersion 3と既存APIは維持。追加クエリは任意。既定の接続先は変更しない。
- Python試験77件、JavaScript試験91件成功。処理枠の並行進行、履歴/編集保持、Windows強制終了時の子プロセス終了を含む。
- 合成音声のTiny/CPU認識、モデル再利用、リアルタイム枠、中止を実検証。ZIP展開後のEXEでもBearer認証と実認識を検証。
- Web画面で履歴の枠絞り込み、字幕再表示、稼働/容量表示、整理確認画面とキャンセルを確認。

## 移行前の確認

- 別PCからはサーバーモードとBearer認証を使用。移行先URL/認証は各利用アプリでも対応・設定が必要。
- GPU、実移行先PC、長時間実会議の品質と同時負荷の受入は未完了。
- GPU処理中へのリアルタイム割り込み、speech.cppのモデル常駐化は行わない。
