# TranscriptionServer v0.1.14

- 同じモデル・異なるモデルへの要求を最大10件まで並列処理します。既定はリアルタイム予約2枠、GPU最大2件です。
- リアルタイム要求を優先し、RAM／VRAMの見積り予算を超える要求は理由付きで待機します。手動常駐モデルも計上し、個別取消や失敗時のプロセス解放を要求ごとに管理します。
- 管理画面に並列数・メモリ予算設定と実行／待機状況を追加しました。
- GET /api/scheduling、POST /api/management/scheduling、healthのconcurrentInference/resourceBudgetScheduling、モデルカタログのexecution件数を追加しました。protocolVersion=3と既存の認識APIは維持します。
- クライアントはstatus=queued / phase=waiting_resourcesを失敗として扱わず待機表示してください。詳細はdocs/concurrent-execution.mdを参照してください。

RAM／VRAM制御は見積りによる開始制御であり、OSによる使用量の強制制限ではありません。常に10件の実推論や一定の応答時間を保証するものではありません。

合成試験で10件同時開始・11件目待機・リアルタイム優先・個別取消と結果分離を確認。実モデルは隔離環境のWhisper Tiny/CPUで7件完了・最大6件同時処理を確認済み。実GPUの並列負荷、異なるエンジン混在の実推論、大型モデルの同時実行、長時間負荷、各利用アプリの通し確認は未実施です。

Windows x64ユーザー単位setup、Windows ZIP、ソースZIP、SHA256SUMS.txtを提供します。モデル・認識実行環境は同梱しません。本PCの稼働サーバーや利用アプリは今回更新していません。
