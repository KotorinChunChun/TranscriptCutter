TranscriptionServer v0.1.9 / Rust CLI・HTTP/API / Windows x64

## 変更点

- モデルの「導入」を1つにまとめ、不足する実行環境→モデルの順に取得します。導入済みの実行環境は再利用し、新しい環境の反映にサーバー再起動が必要な場合は対象名を表示します。PCの再起動は不要です。
- 確認付きの「モデルを削除」を追加。ロード済みモデルや処理・待機・転送・更新と競合する操作は拒否し、録音・字幕・設定・実行環境・他のモデルを保持します。
- モデルを用途別の一覧表へ変更。「モデル」「状態」「保存容量」の見出しクリックで並べ替え、再クリックで反転します。簡易表示と従来の全項目を残す詳細表示を切り替えられます。
- 「ロード・アンロードの対象」を各モデルの操作欄へ移動。選択したモデルのファイル処理枠/リアルタイム処理枠へ適用し、表示・並べ替え後も選択を維持します。
- ヘッダーを固定し、接続済み表示の重複と「導入を確認」を整理。進捗・完了・失敗メッセージに対象名を付けました。

## 配布・連携

setup-x64.exe、program-only Windows ZIP、source ZIP、SHA256SUMS.txtを提供します。認識ランタイム・Python・FFmpeg/FFprobe・モデルは同梱せず、管理画面から必要なものをオンライン導入します。追加PythonはWhisper認識ワーカー専用です。

protocolVersion=3、CLI、文字起こし・ジョブ・話者分離APIは維持します。管理APIのモデル一覧にはdeletableを追加し、`POST /api/management`の`install`は不足する実行環境も順次準備します。モデル削除は`{"action":"delete","model":"whisper/tiny","confirm":"delete-model"}`です。管理モデル一覧全体を実行候補とみなさず、従来どおりhealth/v1/modelsを確認してください。

既存の稼働サーバーへは自動適用していません。インストーラーの適用と再起動が必要です。

Rust 55件、Web 111件、Whisperワーカー3件、fmt/clippyが成功。見出しクリックの昇降順、状態優先、キーボード操作、モデルごとの対象保持、簡易/詳細の全項目を表示専用プレビューで確認しました。合成環境で反映待ち実行環境からのモデル準備、削除対象の限定、ロード/待機中の削除拒否を確認しています。
