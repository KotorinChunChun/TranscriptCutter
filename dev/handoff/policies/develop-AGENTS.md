# このPCのWebサーバー公開ルール

C:/develop配下の全プロジェクトに適用する（2026-10-01ユーザー指定）。

- **対象は他のPCからもアクセスするサーバープログラムに限る**（2026-11-10ユーザー指定）。LAN・社内に公開するもの、`0.0.0.0`やこのPCのLANアドレス（192.168.x.x）で待ち受けるもの、他のPCから呼ばれる内部APIが対象。
- `127.0.0.1`/`localhost`だけで待ち受け、このPCの中でしか開けない開発・画面確認用のサーバー（テストハーネス、`gulp serve`、Viteの開発サーバー等）は対象外で、DevServerへの掲載・予約なしで起動してよい。ただし使用中の番号は奪わず（相手を確認し、他のプロセスを止めない）、台帳で予約済みの番号は避ける。後から他のPCに公開するときは、その前に以下の手順を行う。
- 対象のWebサーバーや内部APIを、本番・開発・検証・一時検証のどれであれ新設・公開する前に、C:/develop/DevServer/PUBLISHING-POLICY.mdを読む（同書の「一時的な画面確認を含む」は、他のPCからアクセスするものに読み替える）。
- DevServer（http://127.0.0.1:19000/）への掲載と空きポートの事前予約を必須とする。正本はC:/develop/DevServer/local/servers.json。停止中や予約済みの番号を空きと扱わない。
- 最新の実待受とWindowsの除外・動的範囲を確認し、Reserve-ServerPort.ps1または正式更新CLIで予約を確定してから固定番号で起動する。競合時に番号を自動変更したり、他のプロセスを勝手に停止したりしない。
- Entra ID認証を推奨する。必要なID、URI、権限・同意状態、資格情報の保管場所・期限、実サインイン確認状況はDevServerで管理する。未導入・内部APIには方針と理由を記録する。
- シークレット値・秘密鍵・トークン・パスワードを台帳・画面・Gitへ記録しない。保護された実値の保管参照だけを管理する。
- 設定済みと実サインイン確認済みを区別する。掲載や予約は認証登録・公開範囲拡大の許可を意味しない。
- PowerShellの実行はpwshを使用する。各リポジトリの開発・検証・コミット規則も守る。

- 指示がない限り本番サーバーは触らない（2026-10-01ユーザー指定）。本番サーバーへの操作は、ユーザーが対象と操作内容を明示して指示した場合だけ行う。
- 機能追加・修正の依頼だけで本番反映、起動・停止・再起動、配布先・設定・認証・ネットワーク・データの変更、本番へ接続する検証を行わない。通常の実装・検証は開発・検証環境で行う。
- 過去の本番操作指示を将来の包括的な許可として扱わない。

## コマンド操作の注意（プロジェクト共通ルール）

2026-10-12の作業で実際に起きた失敗の再発防止。

- pwshで`[IO.File]::ReadAllText`等の.NETメソッドへ相対パスを渡さない。.NETはプロセスのカレントディレクトリ基準で解決し、`cd`/`Set-Location`に追随しないため、別の場所に空ファイルを作った。必ず絶対パスを渡す。読み込みに失敗したら書き込みへ進まない。
- 文字列置換でファイルを編集する前に改行コード（CRLF/LF）を確認する。Prettierは既存の改行を保つため、テストファイル等はCRLFのことがあり、LFのパターンが一致しない。
- `ConvertFrom-Json`の数値はInt64になる。ハッシュテーブルのキーに使うときは文字列に変換してから比較する。
- `detected dubious ownership`が出たリポジトリでは、グローバル設定を変更せず、コマンドごとに`git -c safe.directory=<リポジトリの絶対パス>`を付ける。

## 共通HTTPS証明書（2026-10-15ユーザー指定）

- このPCのHTTPSは原則example-Dev-Serverを共用し、C:/develop/DevServer/TLS-POLICY.mdを正本とする。新規・変更時に必ず読み、共通パスを参照する。アプリごとの自己署名証明書を通常起動で自動生成しない。
- 証明書はC:/AI/Certificates/example-Dev-Server.crt、対応秘密鍵は同名.key。利用PCへ渡すのはexample-Dev-RootCA.cerだけ。CA発行鍵・サーバー鍵・アプリ署名・Entraクライアント認証を混同しない。
- 既存サービスは担当チャットで対象・設定・所有・保護バックアップを確認して段階移行する。共通ルールの制定は全本番サーバーの一括切替・再起動や利用PCへの信頼登録の承認ではない。秘密鍵の読取は必要なサービス実行者だけに限定し、再発行・更新はDevServer管理で行う。
