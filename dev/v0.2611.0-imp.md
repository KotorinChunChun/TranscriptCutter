# v0.2611.0 実装計画・報告書

## 構成

- Windowsの独立EXE（Tauri 2）。画面をアプリへ埋め込み、HTTPポートやWebホスティングは新設しない。
- 既存「会議文字起こし」から時刻・字幕出力の共通ヘルパーを移植。目的を動画の認識・検索・修正・再生・範囲指定・カットへ絞る。既存画面とサーバーは削除・変更しない。
- Rustクライアントが既存TranscriptionServerの/api/health、/v1/models、/api/jobsへ接続し、トークンはメモリ内だけで保持する。既定127.0.0.1:8769、同じPCのloopback HTTPのみ。ブラウザー内推論・モデルの複製・新しい推論サーバーは作らない。
- アプリ自身の動画プロジェクト・カット範囲・元ファイル参照を専用データへ保存する。認識結果・編集は既存サーバーへ保存し、アプリを閉じても受付済み認識はサーバーで継続する。
- 動画の選択と保存先はアプリ内ブラウザー。OS標準ダイアログは使わない。登録した動画と書き出しだけをasset protocolへ許可する。
- FFmpeg/FFprobeは既存インストールまたはアプリ隣接binから参照。選択範囲を残す/除くMP4書き出しと複数範囲の連結を実装。正確な範囲でH.264/AACへ再エンコードし、元動画・既存出力を上書きしない。FFmpegはアプリ側、推論はサーバー側と責務を分離する。
- 初回モデル取得などはサーバーの既存動作に従う。外部APIへ自動切替しない。未対応モデル・GPU・話者分離は能力情報に従って扱う。

3. 合成動画で認識→結果→範囲→動画出力・中止・既存保持を実接続で検証。独立EXE作成・起動確認、資料を完成してコミット。

- 業務動画や実録音は使わず、合成動画/音声で検証する。Tiny/CPUの実認識と画面/マイク/GPU/精度受入は分ける。

## フェーズ3結果・最終構成

- 実装はC:\develop\TranscriptCutterの独立Gitリポジトリ。推論は既存TranscriptionServer、動画処理は独立EXE側のFFmpeg/FFprobeへ分離した。HTTPホスト・ポート・推論モデルの複製はない。既存の会議文字起こし画面、AI Room、MeetingVisualizer、DevServer設定は変更していない。
- カット方法を比較・修正：範囲ごとにMP4を作って結合する方式にはAACの遅れが範囲数分積み重なる可能性があった。映像・音声を一緒にconcatする方式も、0.1秒範囲20個で映像フレーム丸めが蓄積し、長さの検証に失敗した。最終的に映像フレームをselect/setptsで残す時間軸へ直接写像し、音声をatrim/apad/concatで連結して1回だけH.264/AACへエンコードする方式を採用。20範囲の長さが期待2秒から0.12秒以内になる試験が成功した。
- Windowsでは読取専用ハンドルのsync_allがアクセス拒否になることを実試験で確認。生成した一時出力だけを書込可能で開いて同期するよう修正した。元動画は読取だけで、同期・書込対象にしない。
- 生成出力は同一保存先配下の専用一時フォルダーで処理し、検証後persist_noclobberで確定。大きな動画の余分な全体コピーを避け、既存の保存先ファイルを保持する。
- サーバーの話者識別可否は/v1/modelsの能力情報に従う。字幕修正後には再取得してmanual等の話者由来も保持。カット後の字幕・話者区間を出力時間軸へ変換する。
