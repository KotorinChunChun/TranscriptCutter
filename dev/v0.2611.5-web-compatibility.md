# Web版の機能点検（v0.2611.5）

比較元は受領ZIPのVTT Dialogue v3.4、統合Web版v0.2611.4、文字起こしサーバーの従来Web画面です。コード/単体試験の確認と、実ブラウザーで操作した範囲を区別します。「全機能の実機合格」という報告ではありません。

## 見つかった回帰と今回の修正

| 項目 | v0.2611.4の状態 | v0.2611.5 |
|---|---|---|
| 処理中の確定字幕 | サーバーへ保存されてもcompleteになるまで取得しない | 1.5秒間隔で増分取得。工程2にいても継続 |
| エラー/中止後の確定字幕 | 新しい画面から取得できない | 履歴から取得し、部分結果と明記してVTT保存 |
| 認識範囲を指定した進捗 | 元動画全長を分母にしていた | 開始〜終了の対象範囲で計算 |
| 200件を超える字幕 | 画面は先頭200件のみ。工程2へは全件引継ぎ | ページ移動で全件閲覧、最新字幕の追従 |
| 処理の見通し | 状態名とバーが中心 | 到達時刻、段階、経過秒、保存/取得件数、最終更新、モデル/デバイス |
| VTTの識別 | 手動保存では元動画名だけ | this-PC/server、エンジン、モデル、complete/partial、ジョブID |

実サーバーの失敗ジョブ457件を画面に読み込み、201〜400件への移動と工程往復で保持を確認しました。実Downloadsへエンジン名付き部分VTT（47,165 bytes）を保存できました。合成APIで認識中の段階/字幕件数の増加、別工程中のポーリング継続、処理中のモデル/接続/履歴変更の禁止を確認しました。

今回のWhisper Baseエラーは、工程切替を行わないAPI比較でも同じ2393.94秒で再現しました。旧サーバーv4.2.0のWhisperワーカーは5分チャンク外などの不正な時刻でこのエラーを返します。問題の生の数値は保存されておらず、どの条件に該当したかは未確定です。画面切替が原因ではありません。

## 操作の変更・制約として残るもの

- ファイル入力はアプリ内ドロップが主経路です。原ZIPの「ファイル選択」を押してOSの選択画面を出す動作は引き継いでいません。現画面の「ファイルを選択」「動画・音声を読み込む」はドロップ受付を開きます。VTTは貼付も可能です。OS標準ダイアログへ依存しない共通UI指示に合わせた変更ですが、従来のクリック選択と同じ操作性ではありません。
- 原ZIPの「名前を付けて保存」（showSaveFilePicker）は無効にし、ブラウザーのダウンロードを使用します。出力内容の表示/コピーは維持しています。指定フォルダーへの直接保存とは異なります。
- 選択/編集とFile参照は同じブラウザータブ内のメモリに保持します。工程往復は維持しますが、タブ終了/再読込をまたぐ自動復元はありません。プロジェクト保存と元動画の再読込が必要です。
- 元ZIPにもあったブラウザー/OSのコーデック制約と音量解析のサイズ/長さ制限は残ります。MP4出力を全端末で保証していません。

## 従来の文字起こしサーバーWeb画面との違い

工程1に既存サーバーを使うユーザー指定に従い、TranscriptCutterはサーバー認識と工程2の編集へ導線を統合しています。サーバー自身の従来画面を置換・削除していません。

- 従来画面にあるブラウザー内Whisper実行、外部APIモデル、SRT/TXT出力、サーバー保存字幕への直接編集・保存、接続プロファイル/運用・更新画面はTranscriptCutterへすべて移植したわけではありません。
- TranscriptCutterの工程2はコピーしたVTTを編集します。認識サーバー上の保存済み字幕へ自動で書き戻しません。VTT・編集プロジェクト等で編集結果を保存します。
- サーバー履歴の音声・字幕は保持されています。今回も失敗ジョブを変更せず読み取りで回収しました。サーバー自身の画面の全導線は今回の実機点検対象外です。

これらを含めて「元のWeb版のすべてが同じ操作でできる」とは言えません。特に途中字幕と200件上限の回帰を今回修正し、入出力の操作差とサーバー画面固有機能は上記のとおり残しています。
